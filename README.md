## Тест дизайн

Тестлэгдэх функц нь `POST /registrations`. Оролт нь body доторх studentID ба courseID, мөн сервер дээр урьдчилан тавьсан оюутан, хичээлийн бичлэг.

### Сонголт ба төлөөлөх утга

| Сонголт | Анги | Төлөөлөх утга |
|---|---|---|
| studentID | идэвхтэй | B231234567, status active |
| | идэвхгүй | B231000003, status inactive |
| | байхгүй | B239999999, PUT хийгээгүй |
| | талбар дутуу | body-д studentID байхгүй |
| Оюутны үзсэн хичээл | урьдачаа бүгд үзсэн | ["CS201"], CS313-ийн хувьд |
| | огт үзээгүй | ["MATH101"] |
| | заримыг нь үзсэн | ["CS201"], CS320-ийн хувьд |
| | хоосон | [] |
| courseID | байгаа | CS313 |
| | байхгүй | CS999 |
| Хичээлийн урьдач | нэг | CS313: ["CS201"] |
| | хоёр | CS320: ["CS201", "CS202"] |
| | урьдачгүй | CS100: [] |
| Body | буруу JSON | `{"studentID": "B231234567", "courseID": ` |

### Спецификаци

| # | Спецификаци | Статус | result |
|---|---|---|---|
| 1 | Идэвхтэй оюутан, урьдачаа үзсэн, хичээл байгаа | 201 | OK |
| 2 | Оюутан байхгүй | 200 | ERROR_NO_STUDENT |
| 3 | Оюутан идэвхгүй | 200 | ERROR_INACTIVE_STUDENT |
| 4 | Хичээл байхгүй | 200 | ERROR_NO_COURSE |
| 5 | Урьдачаа огт үзээгүй | 200 | ERROR_PREREQUISITES, missing ["CS201"] |
| 6 | Оюутан идэвхгүй ба хичээл байхгүй (давхар алдаа) | 200 | ERROR_INACTIVE_STUDENT |
| 7 | Хоёр урьдачийн зөвхөн нэгийг үзсэн | 200 | ERROR_PREREQUISITES, missing ["CS202"] |
| 8 | Урьдачгүй хичээл, coursesTaken хоосон (хязгаар) | 201 | OK |
| 9 | studentID дутуу (хязгаар) | 400 | ERROR_BAD_REQUEST |
| 10 | Буруу JSON (хязгаар) | 400 | ERROR_BAD_JSON |

Боломжгүй хослолууд:
- Оюутан байхгүй бол түүний үзсэн хичээл гэж байхгүй, тиймээс "байхгүй оюутан" нь үзсэн хичээлийн ангиудтай хослохгүй.
- Хичээл байхгүй бол урьдач нөхцөл гэж байхгүй.
- Сервер эхлээд оюутныг, дараа нь хичээлийг шалгадаг тул идэвхгүй оюутан байхгүй хичээлд бүртгүүлэхэд хичээлийн алдаа хэзээ ч харагдахгүй. 6-р спецификаци үүнийг шалгана.

## Collection

[lab05-collection.json](lab05-collection.json) дотор спецификаци бүр тусдаа folder. Folder бүр өөрийн оюутан, хичээлийг PUT-ээр бэлдээд `POST /registrations` илгээнэ, тиймээс ганцаараа ч ажилладаг. Серверийг дахин асаагаад folder бүрийг `newman run --folder`-оор дангаар нь ажиллуулахад бүгд давсан. Сервер өгөгдлөө санах ойд хадгалдаг тул registrationID ажиллуулах бүрд өсдөг, иймээс яг утгыг нь биш, тоо эсэхийг нь л шалгасан.

## Newman

```bash
newman run lab05-collection.json 2>&1 | tee results/newman-pass.txt
echo "exit=$pipestatus[1]"
```

`| tee`-ийн дараа `$?` нь tee-ийн код болдог тул exit code-ийг zsh-ийн `$pipestatus[1]`-ээр авсан.

| Ажиллуулалт | Файл | requests failed | assertions executed | assertions failed | exit |
|---|---|---|---|---|---|
| PASS | [newman-pass.txt](results/newman-pass.txt) | 0 | 39 | 0 | 0 |
| FAIL | [newman-fail.txt](results/newman-fail.txt) | 0 | 39 | 1 | 1 |
| DOWN | [newman-down.txt](results/newman-down.txt) | 23 | 39 | 36 | 1 |

Өөрийн API-д 10 тест байгаа, спецификаци бүрд нэг folder, нэмэлтээр нийтийн API-д 1 тест. Нийт 39 assertion ажилласан, үүнд setup PUT-үүдийн "Setup амжилттай" шалгалт ч орсон.

FAIL-д [lab05-collection-fail.json](lab05-collection-fail.json)-ийн 1-р тест 201-ийн оронд 200 хүлээдэг болгосон. Гаралтад `expected response to have status code 200 but got 201` гэж гарсан. Үндсэн collection зөв хэвээр.

DOWN-д серверээ унтраагаад ажиллуулахад localhost руу явсан 23 хүсэлт бүгд `connect ECONNREFUSED 127.0.0.1:3000` гэж унасан, харин jsonplaceholder руу явсан ганц хүсэлт давсан. FAIL-д сервер хариу өгсөн ч миний хүлээлт буруу байсан бол DOWN-д сервер огт хариулаагүй, өөрөөр хэлбэл энэ нь oracle-ийн биш холболтын буюу интерфейсийн алдаа юм.

## Нийтийн API

Collection-ийн сүүлд `https://jsonplaceholder.typicode.com/users` руу GET хийгээд 3 oracle тавьсан: статус 200, хариу массив, эхний хэрэглэгч "Leanne Graham". Setup хэрэггүй, ганц хүсэлтээр шалгадаг нь хялбар байсан ч өгөгдөл нь өөр хүний гарт байгаа тул тэр нэрийг хэн нэгэн өөрчилбөл миний тест унана, харин өөрийн API-д өгөгдлөө setup-аар өөрөө тавьдаг.

## Дүгнэлт

Дизайны 5 алхмаас хамгийн их бодол шаардсан нь төлөөлөх утгыг сонгох алхам байсан. Жишээ нь "урьдачийн заримыг нь үзсэн" ангийг шалгахад нэг урьдачтай CS313 хангалтгүй байсан тул хоёр урьдачтай CS320 хичээлийг тусад нь үүсгэх хэрэгтэй болсон. Спецификаци бичихэд сервер оюутныг хичээлээс өмнө шалгадаг гэдгийг мэдэхгүй бол давхар алдааны хүлээгдэх үр дүнг буруу бичих байсан. Боломжгүй хослол хоёр таарсан: байхгүй оюутанд үзсэн хичээл гэж байхгүй, байхгүй хичээлд урьдач нөхцөл гэж байхгүй. Тестүүд бие даасан байхын тулд folder бүр өөрийн оюутан, хичээлийг PUT-ээр бэлддэг болгосон бөгөөд серверийг дахин асааж folder бүрийг дангаар нь ажиллуулахад давсан. 10 спецификаци бүгд хүлээгдэж буй үр дүнгээ өгсөн тул спецификацийн хүрээнд согог олдоогүй. Гэхдээ эхэндээ curl-ээр туршиж байхад нэг оюутан нэг хичээлд хоёр удаа бүртгүүлэхэд хоёулаа 201 OK авч давхар бүртгэл үүсэж байсныг анзаарсан. Спецификацид энэ тухай юу ч заагаагүй тул тест бичээгүй ч бодит системд энэ нь согог болох магадлалтай. Харин AI-ийн олсон `null` body ба `constructor` гэсэн courseID серверийг бүр унагасан тул миний спецификацууд кодын ийм хэсгийг огт хамраагүй байжээ. FAIL ба DOWN хоёулаа exit 1 өгсөн ч нэг нь oracle-ийн, нөгөө нь холболтын алдаа байсныг requests failed баганаас ялгаж болдог нь сонирхолтой байлаа.

## AI өнцөг (нэмэлт)

server.js-ийг Claude-д өгөөд зааврын prompt-оор шинэ чат дээр асуусан, хариуг нь засалгүй [ai/ai-design.md](ai/ai-design.md)-д хуулсан. AI миний бүх ангийг олсноос гадна миний мартсан "өмнө нь бүртгүүлсэн эсэх", хоосон string ID, хоосон `{}` body зэрэг ангийг нэмсэн. Хамгийн чухал нь AI код уншаад гурван согог олсон: `toString` гэсэн studentID нь ERROR_NO_STUDENT биш ERROR_INACTIVE_STUDENT буцаадаг, `null` body ба `constructor` гэсэн courseID серверийг бүр унагадаг, би curl-ээр шалгаж гурвууланг нь баталсан. Шалтгаан нь сервер оюутан, хичээлээ энгийн `{}` объектод хадгалдаг тул JavaScript-ийн объектод угаасаа байдаг нэрс "олдчихдог" юм байна. Харин AI-ийн нэг oracle лабын шаардлагыг зөрчсөн: GET /registrations тест нь бүртгэлийн ID-г яг [1, 2, 3, 4] гэж шалгадаг тул серверээ дахин асаахгүйгээр хоёр дахь удаа ажиллуулахад унана. Мөн бүх тест нэг нийтлэг "00 Setup" folder-оос хамаардаг, дарааллаар нь ажиллуулах ёстой тул тестүүд бие даасан биш. Давхар бүртгэлийн тестэд 201 хүлээж одоогийн байдлыг л баталсан тул согог мөн эсэхийг шийдээгүй. Нийтдээ шинэ анги, согог олоход AI надаас давсан ч тестийн бие даасан байдал ба oracle-ийн найдвартай байдалд миний хувилбар дээр байсан.
